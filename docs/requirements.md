# 요구사항

표기: **[사용자]** 는 사용자가 정한 것, **[Claude 결정]** 은 Claude가 정한 것(사용자 검토 대상)이다.

## 1. 플레이 방식
- R1. 방문자 누구나 플레이할 수 있다. 모든 방문자가 **하나의 공유 판**을 이어서 진행한다. [사용자]
- R2. 행동 입력은 README의 링크 → 미리 채워진 새 Issue 제출로 한다. 행동은 Issue 제목으로 구분한다: `blackjack-deal`, `blackjack-hit`, `blackjack-stand`, `blackjack-reset`. [사용자]
- R3. Issue 본문에는 "내용을 바꾸지 말고 제출만 하세요" 안내를 미리 채운다. 처리 시 본문은 보지 않는다. [사용자 승인]
- R4. 제목이 `blackjack-`으로 시작하지 않는 Issue는 게임이 건드리지 않는다. [사용자 승인]

## 2. 칩
- R5. Reset 시, 누가 누르든 소유자 `how-to-song`의 **최근 1년 기여 수**(프로필 잔디 숫자, `contributionCalendar.totalContributions`)를 조회하여 기여 1 = 🪙 1 칩으로 설정한다. [사용자]
- R6. 기여 수가 10 미만이면 시작 칩을 10으로 보정한다. [사용자]
- R7. 칩은 판 하나에 하나만 존재하며, Deal로 다음 판을 시작해도 유지된다. [사용자]

## 3. 행동과 상태
| 상태 | 가능한 행동 |
|---|---|
| `idle` (판 시작 전) | Deal, Reset |
| `playing` (플레이어 턴) | Hit, Stand |
| `finished` (판 종료) | Deal, Reset |
| `broke` (파산) | Reset |

- R8. Deal: 칩이 10 이상일 때만 가능. 베팅금 10을 차감하고, 새로 셔플한 52장 덱에서 플레이어와 딜러에게 2장씩 나눈다. [사용자]
- R9. Hit: 플레이어가 1장 받는다. 21을 넘으면 즉시 플레이어 버스트로 판이 끝난다. [사용자]
- R10. Stand: 딜러의 숨긴 카드를 공개하고, 딜러가 규칙대로 뽑은 뒤 판정한다. [사용자]
- R11. Reset: `idle`, `finished`, `broke` 상태에서만 가능하다. 판 진행 중(`playing`)에는 막아서, 다른 사람이 진행 중인 판을 날릴 수 없다. R5로 칩을 다시 설정한 뒤 `idle`이 된다. 판 중에 막힌 Reset은 횟수에 세지 않는다. [사용자]
- R12. 판이 끝난 뒤 칩이 10 미만이면 `broke`가 된다. [사용자]
- R13. 현재 상태에서 할 수 없는 행동은 상태를 바꾸지 않고, Issue에 안내 댓글을 단 뒤 닫는다. [사용자 승인]

## 4. 블랙잭 규칙
- R14. 조커 없는 52장 1덱. 매 Deal마다 셔플. [사용자]
- R15. 2~10은 숫자대로, J/Q/K는 10. Ace는 플레이어·딜러 모두 21을 넘지 않으면 11, 넘으면 1. [사용자]
- R16. 블랙잭(처음 두 장이 Ace + 10점 카드)은 Deal 직후 확인하여 즉시 판정한다. 플레이어만 → 플레이어 블랙잭 승리, 딜러만 → 딜러 승리, 둘 다 → push. [사용자 승인]
- R17. 딜러는 17 이상이 될 때까지 뽑고, Soft 17에서도 멈춘다(S17). [사용자]
- R18. 정산(베팅 10 기준, Deal 때 이미 차감): 블랙잭 승리 +25 (반환 10 + 15), 일반 승리 +20, push +10, 패배 0. [사용자]

## 5. 덱 비공개
- R19. 공개 저장소 파일과 Actions 로그 어디에서도 남은 덱 순서와 딜러의 숨긴 카드를 알 수 없어야 한다. [Claude 결정: 방법은 architecture.md]

## 6. 남용 방지
- R20. Reset은 **한 사람당 하루 최대 5번**. 6번째부터는 판을 바꾸지 않고 "오늘 Reset 횟수를 다 쓰셨습니다" 댓글을 단 뒤 닫는다. [사용자]
- R21. 하루의 기준은 한국 시간(KST, UTC+9) 자정이다. [Claude 결정]
- R22. Reset 외의 행동은 횟수 제한을 두지 않는다. [사용자: 그냥 두어도 된다는 데 동의]
- R23. 처리가 끝난 게임 Issue는 결과 댓글을 단 뒤 Close 및 Lock한다. [사용자]

## 7. 화면 (README)
- R24. 게임은 README의 `<!-- blackjack -->` … `<!-- /blackjack -->` 구간에만 그린다. 구간 밖은 바꾸지 않는다. [사용자 승인]
- R24-1. 게임 구간은 README **맨 위**, 기존 Tech Stacks보다 위에 둔다. [사용자]
- R25. 게임판은 HTML 표에 카드 SVG 이미지를 배치하는 형태(A안)다. 딜러 줄, 플레이어 줄, 각 줄의 합계를 보여준다. [사용자]
- R26. 플레이어 턴 동안 딜러의 두 번째 카드는 뒷면 이미지로, 딜러 합계는 `?`로 보인다. [사용자 승인]
- R27. 보유 칩과 베팅금을 표시한다. [사용자 승인]
- R28. 현재 상태에서 가능한 행동의 버튼만 보여준다. [사용자]
- R29. 판이 끝나면 결과(예: "블랙잭 승리!", "딜러 버스트")를 표 위에 크게 보여준다. [사용자]
- R30. 행동 기록 표: 행동, 결과 내용, 행동한 사람(GitHub 계정 링크)을 최근 순으로 보여준다. [사용자]
- R31. 게임 구간 위쪽에 "🤖 링크를 누른 뒤 약 1분 후 새로고침(F5)해 주세요!" 안내와 마지막 갱신 시각(KST)을 표시한다. [사용자 승인]
- R32. 카드 그림은 공개적으로 쓸 수 있는 라이선스(퍼블릭 도메인 또는 CC0 등)의 SVG 카드 세트를 사용한다. [사용자]

## 8. 신뢰성
- R33. Issue가 연달아 들어와도 상태가 꼬이거나 Issue가 처리되지 않은 채 남지 않는다. [사용자 승인]
- R34. 기여 수 조회가 실패하면 판을 바꾸지 않고, 실패 안내 댓글을 단 뒤 닫는다. 이때 Reset 횟수는 차감하지 않는다. [Claude 결정]
